01 / 交互原理

三条路径，一套采集后端

切换路径，看清谁在发请求。

公开 Python 版：登录后，通常由程序直接请求

源码已核对
  1. 1浏览器登录

    你在抖音网页完成登录，建立会话。

  2. 2读取 Cookie

    程序获得会话与浏览器相关信息。

  3. 3Python 发请求

    携带参数、请求头和签名，访问网页接口。

  4. 4平台返回数据

    接受请求后，返回搜索、评论或作品资料。

登录过 ≠ 后续请求都经过浏览器

这是公开版的主要路径。Cookie 能提供会话信息，但不能保证通过平台的环境校验与风控。

02 / 能力与效果

同一套请求基础，三种不同产出

展开查看处理步骤与能力边界。

A搜索与热榜从关键词得到作品列表，从热榜得到时间快照JSONL

怎样实现

关键词 → 抖音网页搜索接口 → 提取作品信息 → 游标翻页 → 按 ID 去重 → 保存。热榜直接获取词条列表，按采集时间形成快照。

匹配和排序由抖音完成。库没有自己建立搜索引擎，也不会把结果自动全部下载。

B视频、图集与音乐下载先获取作品资料，再从媒体服务器取文件媒体文件

怎样实现

短链跳转 → 作品 ID → 详情与媒体地址 → 优选来源 → 分块写入临时文件 → 长度校验与归档。主页、合集批量下载会先枚举作品。

“无水印”是优选媒体源，不是擦除画面；较高画质不保证作者原始文件。详情被拦截，后续下载也可能无法开始。

C评论与二级回复作品 ID 确定评论区，分页游标控制继续读取JSON

怎样实现

作品 ID → 一级评论接口 → 分页与去重 → 保存 JSON。开启回复后，按评论 ID 额外请求回复接口。

当前自动流程只取每条评论的第一页回复。采集文本不等于完成情绪分析；现成入口主要附在下载工作流上。

保存与整理

直播、回放、语音转写

有直播录制和回放模块。主流程转写服务输出 TXT / JSON；独立本地 Whisper 脚本可输出 SRT。直播仍有实验性限制。

运行与归档

并发、重试、增量与历史

限速、失败处理、已有文件跳过、元数据与 SQLite 历史，组成下载管理基础。去重和重下载受配置影响。

接入其他系统

HTTP 服务与通知

提供下载任务入口、状态查询和通知。服务任务存在内存，重启会丢失；搜索与评论没有独立 HTTP 路由。

05 / 实现与效果的距离

有代码，
不等于当前稳定可用。

  • 会话有效，也可能被风控拒绝。作者披露多项 CLI 核心接口已受限；简单重试或换 Cookie 不一定解决。
  • 浏览器不是全能力保证。主页兜底尚未验证新门禁；桌面桥接是另一条路线，本次未独立实测。
  • 采集不保证完整。二级回复仅第一页；接口返回范围、分页和平台限制都会影响结果。
  • 网页展示的是理解，不是成功案例。没有登录测试、没有实测成功率，也不把合成文件名当真实采集。
