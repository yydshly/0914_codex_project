## E2 · 对齐与节拍控制实验

环境：Python 3.10.11、pypinyin 0.55.0、zhconv 1.4.3。执行 [run_experiments.py](../src/run_experiments.py)，调用上游原始 `align()`、`make_timing.py` 和 `beat_lint.py`。

**人为构造带时间的 ASR 词表，不加载语音模型，也不测真实录音精度。**

| 实验 | 操作 | 实际结果 |
| --- | --- | --- |
| 完全匹配 | 原稿与词表一致 | match = 1.0 |
| 同音错字 | “插件”识别为“差件” | match = 1.0 |
| 英文缺失 | 词表缺 TalkCraft，保留两侧中文 | match = 1.0，英文时间由插值补齐 |
| 低覆盖率 | 多个字不匹配 | match = 0.375，ok = false |
| 整体偏移 | 全部时间推后 2 秒 | match = 1.0 |
| 无锚点 | 中文稿与无关英文词表 | 按预期退出 |
| 逐字展开 | 转换混排时间表 | 全文字符与时间一一对应 |
| 正确节拍 | “十”的落点 2.90 秒 | 返回码 0 |
| 节拍偏移 | 动效时间改为 3.20 秒 | 返回码 1，拒绝 0.30 秒偏差 |
| 镜尾太短 | 落定后仅剩 0.20 秒 | 返回码 1，拒绝停留不足 |

10 项均符合各自预期。**预期被拒绝的输入也算实验通过，不代表其对应视频可交付。**输入、输出和返回码保存在 [experiments/](experiments/)，汇总为 [results.json](experiments/results.json)。

## E3 · 单组件渲染

在 [render-example](../src/render-example/) 中注册上游原始数字组件，不改内容或运动参数。目标为 960×540、30 fps、86 帧的 H.264 MP4。无配音，灰色人物为模板占位。

媒体结果见 `web/dist/render-result.json` 与 `web/dist/assets/number-counter.mp4`。此实验验证 TSX 到视频，不验证全片多镜头管线、真实配音或数字人。

**实际结果：成功。** Remotion 4.0.525、React 19.1.0，复用本机 Chrome。ffprobe 实数为 86 帧、960×540、30 fps、2.867 秒、H.264。抽取 1.9 秒帧确认中文、数字和上游人物占位正常呈现，封面来自这张真实渲染帧。浏览器下载等待曾被取消，随后显式使用本地 Chrome 完成渲染；没有将下载耗时纳入性能结论。
