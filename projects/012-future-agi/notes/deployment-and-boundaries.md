# 自部署条件与能力边界

本页为研究记录，非部署结果或法律意见。编号见[来源索引](sources.md)。

## 环境条件

安装文档列出 Docker Engine 24+、Compose 2.20+、4 核 CPU、至少 8 GB 内存（建议 16 GB）、20 GB 可用磁盘；代码执行服务需要支持 privileged 容器。预构建镜像按该文档为 linux/amd64。以上均为上游要求，未实测资源占用。S05。

当前 Compose 除核心服务，还含采集器、属性目录 Kafka/相关服务和模拟运行器等。安装文档“约12个服务”的概要不能作为当前默认容器数；应对选定版本运行 docker compose config --services 核对，并考虑 profiles 与初始化服务。S06。

镜像有多组版本变量，部分默认 latest 或 local。固定源码提交不等于固定镜像内容；正式复现应记录每个实际镜像 tag/digest。S06。

## 额外依赖

| 能力 | 条件 |
| --- | --- |
| 模型评测与对话模拟 | 模型服务、密钥和配置 |
| 重型 ML 评测 | ML 依赖组与模型资源 |
| 音频评测和语音模拟 | audio / voice 等依赖及语音服务 |
| PII 脱敏 | 对应依赖；文档说明缺少依赖时已启用脱敏的采集会拒绝接收 |
| 自定义代码评测 | 能运行相应隔离代码执行服务的环境 |
| 企业模块 | 对应代码、部署条件和有效许可 |

安装依赖不能替代企业许可，API 密钥不能替代系统依赖。S03、S05、S13。

## 开源与企业范围

根 LICENSE 为 Apache-2.0；LICENSE-EE 单独约束所有名为 ee/ 的目录及其子目录。因此 GitHub 可见不代表全部代码采用 Apache-2.0。S02—S04。

- ee_feature_enabled() 同时检查模块存在与是否非 OSS 部署；这是所读功能注册门控，非全部入口的完整审计。S13。
- 六种优化器目录在 futureagi/ee/agent_opt/optimizers/。T01。
- develop_optimiser.py 和 prompt_template_optimizer.py 导入企业 PromptOptimizer，缺少模块时使用 stub。S21、S22。
- README 提到独立 agent-opt SDK。本轮未审阅其独立版本、许可证和功能对应关系，不能据此推断平台优化全链路免费可用。S01。

## Protect 的不同层次

Protect 产品文档标注 Cloud / Enterprise；仓库同时存在 Go 网关本地防护引擎和检测器。不能概括成所有防护均付费或全部免费。需分别核对本地规则、平台页面、托管 protect()、外部检测器及对应权限。S11、S12、D08。

## 自部署不等于默认离线

README 遥测段说明：默认提交部署注册信息与汇总使用数据；禁用变量关闭常规遥测，但保留一次最小 census ping。模型、语音、外部防护还可能产生其他请求。S01、S20。

这与其他位置 no phone-home 的措辞有张力。若目标是离线运行，应验证实际出口流量和本地模型配置，不能只依据“留空云 API Key”的说明。
