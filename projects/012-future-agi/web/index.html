01 / THE BIG PICTURE

检测 AI 的能力，
看清应用表现。

Future AGI 的核心能力，是检测和评估 AI 应用在具体任务中的表现。它记录执行过程，结合业务标准检查回答与工具使用，帮助发现问题、比较版本并验证改进。

当前理解：能力与检测方式已整理，根本原理需后期深入研究。

目前梳理了规则、参考比较、向量相似度、模型裁判、Agent 调查、工具调用与轨迹匹配。下文和总览图呈现初步实现思路；底层判分、诊断及优化算法仍待深入核验，实际效果尚未实测。

可以把它理解为 AI 应用的记录、评测和诊断平台。这里的 AI 应用包括模型、提示词、知识检索和工具。它记录已接入的输入输出与执行步骤，再从正确性、安全性、语气、工具使用等角度检查表现；这些记录不等于读取模型内部思维，评测分数也要结合业务标准解释。

进一步拆开：七类具体分析手段

“评什么”与“怎么评”要分开。正确性、忠实性、安全性、语气是评测角度；下列方法说明怎样计算或形成判断。它们是对文档与代码的研究归纳，可以组合使用，不是官方定义的七种评测引擎。

01 / 明确条件

规则与函数检查

输入字段 → 条件或函数 → 结果

用正则、包含判断、JSON 解析、数值比较等检查明确要求。纯规则检查无需调用大语言模型；函数型评测也可能使用嵌入等模型。

能判断格式正确，不代表能判断政策正确。

02 / 标准参考

答案与检索指标比较

实际结果 + 人工参考 → 差异或命中分数

BLEU、ROUGE、编辑距离衡量文本与参考的差异；Recall@K、Precision@K、NDCG、MRR 等衡量检索命中与排序，需要预先标注相关结果。

指标依赖参考质量；字词重合不等于意思正确。

03 / 语义距离

向量相似度

文本 → 嵌入模型 → 向量 → 相似度或距离

将文本编码为向量，再算余弦相似度、欧氏距离等。适合衡量语义接近程度，不能替代关键事实核对。

“7 天退款”和“30 天退款”可能很相似，却对应不同政策。

04 / 模型判断

LLM-as-Judge

标准 + 回答 + 上下文 → 提示词 → 模型 → 结构化结果

把业务规则、资料、待测回答和示例拼入评测模板，调用评测模型，解析分数、分类或理由。适合忠实性、完整性、语气和指令遵循等要求。

裁判有费用和波动，需要人工认可样本校准。

05 / 补充证据 · 文档能力

Agent 调查式评测

问题 → 多轮分析 → 工具或知识查询 → 判断

当已有材料不足时，通过工具或知识库补齐证据，再判断任务完成情况或事实依据。它比单次阅读多了一个调查过程。

依赖可用工具和资料；本轮未独立核验完整实现。

06 / 调用匹配

工具调用准确性

实际工具名与参数 + 预期调用 → 匹配评分

已读函数对未使用的预期调用进行匹配：完整匹配计 1，只匹配名称计 0.5，未匹配计 0；总分除以实际与预期调用数的较大值，漏调用与多调用都会影响分数。

工具和参数匹配，不代表接口执行成功；还要核对结果。

07 / 流程结构

执行轨迹匹配

实际步骤序列 + 预期轨迹 → 顺序或集合比较

提供 strict、unordered、subset、superset 等匹配模式，适合检查是否漏掉必要步骤、顺序是否合适或是否有多余调用。例如“先查订单，再决定退款”。不同模式的计分细节应按配置和实现解释。

必须先定义合理的预期流程；固定轨迹不一定覆盖所有正确解法。

D

让评分指导下一轮提示词修改

“自动改进”的核心，是在明确目标下搜索和比较候选版本。

  1. 输入原始提示词
    测试样本与标准
  2. 生成改写提示词
    或调整示例配置
  3. 衡量运行候选
    评测与比较
  4. 反馈保留较好候选
    继续下一轮搜索
独立验收

最后用没有参与优化的样本再测一次。关注严重错误、成本和稳定性，而不仅是平均分。

六种算法，差别在哪里？

Random Search

Bayesian Search

ProTeGi

05 / IN PRACTICE

放进你的业务，会怎么用？

下面是研究者设计的使用示例，不是已运行的测试结果。

CUSTOMER SUPPORT

接口失败了，客服却说“已退款”。

用执行证据验证承诺，找出最终答案背后的错误。

01 / 准备什么

政策与测试工具

提供退款政策、订单数据，让测试退款接口分别返回成功、失败和超时。

02 / 平台怎么参与

记录 → 模拟 → 评测

保存工具结果，模拟不同用户诉求，检查回答和实际执行状态是否一致。

03 / 怎样判断价值

减少错误承诺

核对错误确认、缺少澄清、无效重试等案例；修改后重复相同测试。

一个具体标准退款工具返回失败时，禁止向用户确认退款成功。
RAG / KNOWLEDGE

有知识库，为什么仍然会答错？

将检索质量与回答质量拆开评估，才知道该改哪一步。

01 / 准备什么

问题、片段与回答

保存检索片段，补充人工认可的答案或判断；加入资料不足的问题。

02 / 平台怎么参与

追踪 → 分层评测

先检查片段是否相关，再检查回答是否有依据，识别检索与生成问题。

03 / 怎样判断价值

提高有依据的回答比例

同时看正确拒答、完整性、费用和延迟，不能只看文字相似度。

一个具体标准资料没有国际退货运费规则时，应承认资料不足，不编造政策。
REGRESSION / RELEASE

新版本更便宜，但有没有偷偷变差？

在相同条件下比较，避免只凭几个顺眼的回答选版本。

01 / 准备什么

固定的业务测试集

02 / 平台怎么参与

质量、费用和速度一起看

预先设定业务阈值；对波动较大的指标重复运行，再决定是否发布。
