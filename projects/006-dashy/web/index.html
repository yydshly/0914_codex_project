006 / DASHY / 开源项目研究

把分散的应用入口，
整理成自己的网页工作台。

Dashy 把常用网站、内部后台和服务信息集中到一个可搜索、可编辑的首页。它用网页提供桌面式交互，让你更快找到应用、查看概况；具体业务仍由各个应用自己完成。

它的能力与意义

从“记住很多网址”到“打开一个首页”

01 / 入口

把应用摆在一起

用卡片、分组和多页面整理常用网站、NAS 与内部后台，配上图标、标签、搜索和快捷键。

意义：少记网址，少在收藏夹和后台之间来回找。

02 / 信息

在首页先看概况

通过组件展示时钟、日历、RSS、天气和服务数据；使用 HTTP 或 Ping 检查服务是否响应。

意义：不必逐一进入系统，就能看到常看的信息。

03 / 组织

按自己的工作方式调整

更换主题、布局和排序，直接编辑卡片。支持普通首页、精简页、弹窗和嵌入工作区。

意义：个人、家庭服务器和团队工具都能组织成合适的入口。

更多能力

多语言、响应式界面、可选 PWA、认证与编辑权限、配置导入导出、可选 REST 配置 API、加密备份与恢复。不同能力需要对应配置、服务端或第三方接口。

实现原理

配置生成界面，接口连接服务

查看完整架构 ↗
  1. 1

    描述页面

    YAML 记录页面、分组、链接和组件；浏览器保存个人偏好。

  2. 2

    渲染工作台

    Vue 读取配置，生成卡片、搜索框和动态组件。

  3. 3

    打开或取数

    链接打开应用，组件请求 API；允许时在 iframe 内嵌网页。

  4. 4

    后端补足能力

    Node.js / Express 负责探测、代理、系统信息和配置写盘。

保存到本地写入当前浏览器的 localStorage，属于这台设备的浏览器偏好。

保存到磁盘经后端写入服务器 YAML 文件，需要后端和相应权限。

研究版本使用 Vue 3、Vuex、Vue Router、Vite 与 Node.js / Express；核心配置通常不需要数据库。

一个具体例子

添加一张 NAS 卡片，分别发生什么？

你看到或执行的动作实际由谁完成
点击 NAS 卡片Dashy 提供入口，浏览器打开 NAS 自己的管理网页。
卡片旁的状态灯变绿Dashy 探测目标地址，收到正常响应后显示结果。
首页显示剩余容量接入相应组件，由 NAS API 提供容量数据。
上传、下载或删除文件由 NAS 管理页面或专门业务接口执行；只添加网址不会获得该能力。

最重要的理解边界

桌面式体验，和电脑桌面控制是两回事

需求支持程度具体条件
打开网页应用原生支持卡片保存网址，由浏览器打开。
在工作区内使用网页有条件目标网页允许被 iframe 嵌入。
打开桌面软件有条件应用提供专用协议链接，已在本机安装，浏览器与操作系统允许唤起。
嵌入桌面软件窗口不原生支持原生桌面窗口不能直接作为网页 iframe 嵌入。
执行 exe、命令或自动操作软件需要另接工具需额外本地桥接程序、应用 API 或自动化工具。

统一入口 ≠ 统一接管Dashy 的登录不会自动登录所有链接的应用，也不自动获得它们的业务权限。

状态灯 ≠ 完整监控系统页面轮询不能等同于全天候监控与告警；后端探测反映的是服务器到目标的连通性。

本次验证范围

已验证：原版构建与配置校验、搜索过滤、时钟和本机数据刷新、HTTP 状态从 503 到 200 后状态灯变化、卡片编辑表单、弹窗与 iframe 工作区。

未完整实测：第三方账号接入、认证、云备份、配置写盘完整交互、桌面软件唤起及全部组件。

示例说明：状态切换按钮和本地数据接口由本研究额外编写。Dashy 原生负责嵌入面板、取数、探测和显示；按钮不代表它自带通用服务器控制能力。
