# Dashy 能力与实现总览

核心理解：Dashy 用网页实现桌面式工作台，集中应用入口、信息展示和配置交互。业务功能仍由目标应用提供。这里的“管理”主要指入口、布局和配置管理，不代表接管操作系统或所有应用。

## 能力地图

| 类别 | 能力 | 边界与条件 |
| --- | --- | --- |
| 应用入口 | 网址卡片、分组、多页面、图标、标签 | 添加入口不授予目标系统权限 |
| 搜索与启动 | 名称/域名/标签等筛选、快捷键、外部搜索引擎 | 点击后打开对应网址或交给浏览器处理 |
| 数据组件 | 时钟、天气、RSS、日历、自托管服务统计 | 多数组件需要服务地址、API 或密钥 |
| 状态检查 | HTTP 响应、耗时、ICMP Ping、定时轮询 | 探测通常从 Dashy 服务端发起；页面轮询不能等同于独立全天监控与告警 |
| 打开方式 | 新标签页、当前页、弹窗、工作区、复制链接等 | 弹窗与工作区嵌入受目标网页策略限制 |
| 外观 | 主题、CSS、图标、布局、尺寸、排序 | 原版界面和配置体系内的自定义 |
| 编辑与存储 | 可视化编辑、配置编辑、导入导出、本地保存、写盘 | localStorage 属于当前浏览器；写盘需要后端和相应权限 |
| 认证 | 内置账号、可选服务端 HTTP Auth、OIDC、Keycloak、代理认证 | 配置方式决定保护范围；Dashy 的认证不自动保护或登录被链接应用 |
| 使用体验 | 多语言、响应式、可选 PWA 与基础离线能力 | 离线不等于外部数据和服务仍可访问 |
| 配置备份 | 可选加密云备份与恢复 | 功能存在，本次未验证云服务可用性 |
| 程序化配置 | 可选 REST API | 需主动启用和相应访问权限；属于 Dashy 配置管理 API |

## 实现流程

1. `conf.yml` 描述 pageInfo、appConfig、sections、items、widgets 和 pages。
2. 前端读取并解析 YAML，结合当前浏览器偏好，经 Vuex 管理状态，由 Vue 3 和 Vue Router 组织界面。
3. 卡片通过浏览器链接打开目标；工作区和弹窗通过 iframe 嵌入目标页面。
4. 组件直接调用服务 API，或经 Node.js/Express 的代理取数。后端也负责 HTTP/Ping 探测、系统信息及配置保存。
5. 编辑更新配置对象；本地保存进入 localStorage，磁盘保存经后端写入 YAML。
6. Vite 负责构建。核心配置通常不需要数据库。Docker/Node.js 可提供完整本地服务；单纯静态托管不能独立提供探测、代理、写盘等服务端能力。

## NAS 示例

| 行为 | 谁负责 |
| --- | --- |
| 点击 NAS 卡片 | Dashy 提供入口，浏览器打开 NAS 管理页 |
| 显示绿色状态灯 | Dashy 探测目标地址并展示结果 |
| 显示剩余容量 | 配置的组件从 NAS API 读取数据 |
| 上传或删除文件 | NAS 管理页或专门的业务接口执行，单独添加网址不会自动获得该能力 |

## 桌面应用边界

- 网页应用：原生支持链接打开；允许嵌入时可以出现在 iframe 工作区。
- 桌面软件启动：可通过应用专用协议链接尝试唤起；依赖软件已安装、注册了对应协议，以及浏览器/操作系统允许。软件仍在独立窗口中运行。这是链接机制的条件性接入，本次未实测桌面软件唤起。
- 原生桌面窗口嵌入：未提供。
- 任意执行 exe、脚本、系统命令：未提供通用原生能力。需另接受控的本地桥接程序或管理服务。
- 操作桌面按钮、自动化流程：需额外自动化工具或应用 API。

## 本子项目验证范围

已验证：原版构建与配置校验、搜索过滤、时钟和本机信息刷新、HTTP 状态从 503 到 200 后状态灯变化、编辑表单、弹窗与 iframe 工作区。

本次新增的 `/demo-api/*` 和状态切换按钮用于演示，不属于 Dashy 自带的通用服务器控制能力。本机内存、运行时长和刷新时间是真实数据；正常/维护中服务为明确标记的示例。

未完整实测：第三方账号和密钥接入、各认证方案、云备份、配置写盘完整交互、桌面软件唤起、全部组件和监控功能。
