# 能力、实际用途与验证边界

## 研究对象

用户提供的是 [EvoMap 博客](https://evomap.ai/zh/blog)。本次把官网关联的 [Evolver 仓库](https://github.com/EvoMap/evolver)作为代码主体。网站、协议、客户端和执行宿主不是同一件东西。

| 对象 | 相当于什么 | 工作 |
| --- | --- | --- |
| 网页 | 人的操作入口 | 提问、浏览资产、查看任务与节点 |
| Hub | 经验与协作后台 | 存储、搜索、质量记录、网络任务 |
| GEP | 统一格式与规则 | 描述 Gene、Capsule、事件与标识 |
| Evolver | 经验处理与流程工具 | 选择、构造提示、记录、连接网络 |
| 执行宿主及模型 | 实际干活的人与工具 | 推理、读写项目、执行命令、完成验收 |

## 三个贴近实际的场景

**同一种接口错误反复出现。** 把成功修复归纳为适用版本、请求格式、失败特征、步骤和测试。下次先筛选经验再验证，减少重复查找。接口版本变化仍可能使经验失效。

**团队保留 AI 维护经验。** 不同助手共享结构化步骤与案例，这些材料不依赖单个模型的内部权重。但模型理解力、工具与权限仍影响执行。

**任务需要分析、实现、审查。** 多个 Agent 分工时，经验资产可成为协作材料。这是另一套任务组织能力，不能由本地选择器可用推导出蜂群能交付。

以上是用途推演，没有冒充已完成的业务案例。

## 怎样理解“自进化”

可检查的对象是策略文本、代码变更、运行事件、失败反馈及选择偏好。下一轮依据这些材料调整行为，属于工作流程与外部记忆改进。本次没有训练基础模型，也没有证据证明安装客户端就使任何模型获得原本没有的全部能力。

真正的验收问题是：“相同任务与模型下，经验证的经验是否减少无效尝试？”资产数量、评分、校验通过和多个 Agent 同意，都不能替代这个问题。
