# 画图的原理与底层技术

## 一句话

AI根据内容和设计规范编写HTML/SVG图形代码，浏览器根据坐标、形状、文字和样式将它画出来。模型负责理解和编写，库提供约束、样例与辅助程序，浏览器负责显示。

这套工作流输出的是可读可改的矢量图形代码。文字、矩形、箭头仍是独立元素；不像一张位图，编辑时只能处理像素。

## 两条输入路径

**自然语言/数据 → AI整理事实与关系 → 选择图型与规范 → AI编写HTML/SVG。**

**旧图源文件 → Python解析为中间结构 → AI确认内容并重排 → AI编写HTML/SVG。**

共同后段：结构检查与人工事实/视觉核对 → 浏览器渲染 → HTML、SVG、PNG。

Mermaid在这里提供声明的节点与关系；导入路径不使用其渲染器布局。draw.io用XML或其嵌入容器，Excalidraw用场景JSON；源样式和原坐标通常不带入新图。本次三种简单输入实际提取到相同的6节点5关系。

## 技术分工

| 层 | 技术 | 作用 |
|---|---|---|
| 内容理解 | 宿主大模型 | 提取重点、确认关系、判断读者和表达方式 |
| 规则与参考 | Markdown Skill、图型文档、模板 | 按需提供语义、布局、复杂度和品牌规则 |
| 旧图提取 | Python、XML/JSON/文本解析 | 输出节点、边、分组、方向及预算提示 |
| 布局 | 坐标、几何、间距、路径与比例公式 | 确定图元位置和数据映射；部分图型提供参数化公式 |
| 矢量绘制 | SVG | rect矩形、circle圆、path路径、text文字、marker箭头 |
| 页面与样式 | HTML、CSS | 标题、图形、摘要及统一字体配色 |
| 动画 | 可选的受约束JS控制器与CSS | 按步骤显示、播放状态，保留静态含义 |
| 导出 | SVG提取；浏览器渲染PNG | 单图矢量输出或指定分辨率位图 |

## 坐标是怎样画出图的？

```svg
<rect x="40" y="60" width="160" height="80" />
<text x="80" y="105">接口服务</text>
<path d="M 200 100 H 300" />
```

第一句在指定位置放一个160×80的框；第二句放标签；第三句画水平线。完整图再定义边框、填充、字体、箭头标记和无障碍描述。

布局不仅是画框，还要决定分组、方向、连接端口、拐点、标签位置，以及是否拆图。规则由库提供，许多选择与坐标仍由AI/作者完成。部分类型如Process有确定性布局公式，但这不表示所有类型已有通用自动布局引擎。

## 数据图怎样绘制？

零起点柱状图的一种常用映射是：柱高 = 数值 / 最大值 × 可用绘图区高度。例如50、100、200对应高度比例1∶2∶4。实际实现还要确定刻度、负值、单位、标签和数据域。

折线与散点把数值映射到坐标；矩形树图将数值映射到面积；桑基图将流量映射到带宽。库的设计规范引导实现，输入数据与数学映射仍需核对。

## 哪部分是自动程序，哪部分依赖AI？

- 已有解析器可以程序化提取支持的源文件结构。
- 部分检查可确定性地发现缺失属性、外部引用或特定遮挡。
- 浏览器确定性执行所提供的图形代码。
- 理解自然语言、核实业务关系、合理删减、选图和许多布局决策仍依赖AI/作者。
- 通过检查不证明事实正确；图形好看也不证明逻辑正确。
