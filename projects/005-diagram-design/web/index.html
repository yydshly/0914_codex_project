把已经理解的内容，变成清晰、可编辑的图

Diagram Design 将选图、布局、信息取舍、品牌样式、检查与导出组织成 AI 可执行的工作规范。

这个库能做什么？

让宿主 AI 根据文字、数据或已有图源文件，编写 HTML/SVG 图形代码，再由浏览器渲染并导出 PNG。覆盖架构与部署、流程与交互、层级与组织、数据模型与依赖、时间与工作规划、策略与关系分析、数值与统计，合计 40 种基础图型。

支持品牌样式、深浅主题、分步动画、手绘线条、批注，以及 draw.io / Mermaid / Excalidraw 的结构提取和重绘。适合研究笔记、技术方案、管理汇报、教学说明和流程交接。

三个维度可以组合使用

图形类型决定表达什么结构；表现方式决定静态、动画、主题和细节量；输入来源可以是文字数据，也可以是旧图源文件。

Mermaid 源文件 → 提取流程关系 → 重绘深色流程图 → 添加分步动画 → HTML 演示 / 静态 PNG 分享

主要产物是可编辑矢量图代码，PNG 是渲染结果。当前网页用于阅读和比较已保存的图，不会实时调用模型。

我们怎样使用它？

把 GitHub 项目研究中的能力、原理、输入输出和边界整理为统一中文配图。先核实内容，再选择图型、设定读者与尺寸、生成并检查，最后交付 HTML / SVG / PNG。

与 Fireworks 的技术绘图能力有较多重叠；Graphify 用于关系提取，Archify 用于交互探索。组合仍需要内容映射和来源核实。

已验证到哪里？

155 个原版和 8 个中文案例通过结构及部分遮挡检查；八张中文 PNG 已查看联系表。三种简单源文件均提取出相同的 6 节点、5 关系。

检查通过不证明业务事实正确；复杂导入、逐张原版视觉验收、自动品牌提取和跨工具效率尚未全面验证。

图标原语目录 ↗

一句话理解：AI 按规范写矢量图代码，浏览器负责画出来

例如“用户 → 接口 → 数据库”：AI 先识别三个节点和两条关系，选架构布局，再为每个节点确定位置、尺寸、文字与连线。生成的 SVG 记录这些几何指令；浏览器读取后显示成图。内容理解依赖宿主大模型，执行规则和检查依赖本库的文档、模板与脚本。

从描述开始文字或数据 → AI 整理内容 → 选择图型与规范 → AI 编写 HTML/SVG

从旧图开始源文件 → Python 提取结构 → AI 核实与重新布局 → AI 编写 HTML/SVG

共同交付结构检查 + 事实/视觉核对 → 浏览器渲染 → HTML、SVG、PNG

底层技术怎样分工？

层次技术具体工作
内容与图型大模型 + Markdown Skill理解描述、确定节点关系、选图、读取相应参考文档。
旧图提取Python；XML / JSON / Mermaid 文本解析将支持的源文件整理为节点、关系、容器等中间结构；不在此步骤生成成品图。
布局与数据映射坐标、间距、连线路径、比例公式AI 根据规范写坐标；部分图型提供确定性布局公式。数值图把数值映射为长度、位置或面积。
绘制图形SVGrect 画矩形，circle 画圆，path 画线和曲线，text 放文字，marker 定义箭头。
页面与风格HTML + CSS放置标题、图形和摘要；统一背景、字体、颜色与尺寸。
可选动画受约束的 JavaScript 控制器 + CSS切换显示步骤和播放状态；默认静态，减少动态效果设置下显示完整静态内容。
检查与输出Python + 浏览器；PNG 使用 Playwright/Chromium检查部分结构和遮挡，提取 SVG，渲染 PNG。检查不验证业务事实。

坐标如何变成图？

<rect x="40" y="60" width="160" height="80" />
<text x="80" y="105">接口服务</text>
<path d="M 200 100 H 300" />

意思是：在指定位置画一个框，写上文字，再从框的右侧画一段连线。完整图会增加颜色、箭头、字体和可访问性描述。

数值如何变成柱子？

以零起点柱状图为例：柱高 = 数值 ÷ 当前最大值 × 可用绘图区高度。数值 50、100、200，对应高度比例 1∶2∶4。

各图的映射不同：折线与散点映射到坐标，矩形树图映射到面积，桑基图映射到带宽。设计规范指导实现，数据、口径与数学映射仍需核对。

可追溯模块分解节点输入输出、约束与实现位置

为什么画面会更清楚？

每个节点承担一个明确含义；用一至两个焦点引导注意；复杂内容拆成总览和细节。连线、标签、节点保持间距，图例放在图外。

部分类型给出参数和坐标公式。这仍需要作者或 AI 贯彻执行，不能等同于已有统一的自动布局引擎。

需要理解的边界

  • 检查通过不证明业务事实正确。
  • 导入是重绘，会改变布局，简化需要说明。
  • 单文件可以引用网络字体；离线字体效果可能变化。
  • 动画用于解释顺序，不是视频制作系统。
  • 不适合把数百节点硬塞进一张展示图。
  • 不内置自动扫描任意仓库、追踪代码变化的完整系统。

已有研究，不从零开始

Fireworks 已整理 33 个图型与领域条目：15 项使用原生 JSON，18 项由 AI 按规范绘制后导出，含 3 项近似适配。它们不等于 33 个独立引擎。

Archify 已研究五类图、源码定位、路径追踪与两个模型的差异。Graphify 已用 FastAPI 研究代码提取、查询和增量更新。

这次新增什么？

  • 把产品策略与数据比较类图形也纳入可用样式。
  • 验证三种旧图源文件的提取流程。
  • 观察同内容不同配色、详细程度和完整页面的效果。
  • 补充按读者和用途选择图型的中文导航。

尚无跨工具速度、成本、读者理解率的量化对照，不能据示例数量判断谁更好。
