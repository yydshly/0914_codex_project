# 数据清理与后续处理

**清理不只是删掉 HTML。**我们要的是可追溯、可比较、可重复更新的数据；一个接口返回 JSON，只证明有结构，不证明内容完整、准确或已经跨来源去重。

## 平台已处理到哪里

| 环节 | 已找到的具体证据 | 不能直接推断的事情 |
| --- | --- | --- |
| 正文提取 | AgentKey 的 Firecrawl 支持正文提取；Jina Reader 返回 Markdown [AK04] | 已完成跨网页去重、事实核验或作者识别 |
| 原始 HTML 获取 | AgentKey 的 Bright Data unlock 返回 HTML [AK04] | 一定已经去掉导航与广告 |
| 批量页面处理 | AIsa Firecrawl 有解析、异步抓取与批量入口 [AI04] | 自动完成主题筛选和数据质量审核 |
| 结构化平台响应 | TikHub 返回 JSON [TH01–03] | 各平台字段含义相同、所有分页都已收齐 |
| 预处理数据集 | TikHub 数据集宣称清洗、结构化，首页提及去重 [TH01、TH04] | 所有实时 API 自动继承同样清理；数据集适合任何下游任务 |
| 向量化与排序 | AIsa Jina Embeddings & Rerank [AI05] | 自动解决重复、错时、虚假内容或隐含偏见 |
| 跨市场匹配 | AIsa Matching Markets [AI02] | 任意两个来源的同名对象都可自动合并 |

以上均为文档证据；没有下载付费样本验证效果。链接集中在[证据表](sources.md)。

## 我们需要负责的处理规则

以下为建议设计，不是已实现功能。

| 数据类型 | 建议处理 | 验收方式 |
| --- | --- | --- |
| 网页/文章 | 保留标题、作者、发布时间、正文与链接；去导航、重复段落；保留原件 | 抽查正文是否误删；链接和抓取时间是否齐全 |
| 帖子/笔记 | 用平台+内容ID标识；统一时间和文本编码；原文与翻译分开 | 重复请求不增加相同记录；不能把转发和原帖无条件合并 |
| 评论 | 保留评论ID、父评论ID、作者ID、分页游标 | 回复链不断；记录是否截断、已获取页数，不能声称已获取所有评论 |
| 视频/音频 | 元数据、媒体链接、字幕分别存储；需要时额外转写/OCR并标注来源 | “视频标题”不等于“视频全文”；机器转写与官方字幕可区分 |
| 商品/房产 | 商品、SKU、规格、地区、币种和价格快照分开 | 同商品不同规格不合并；不同币种不直接比较 |
| 金融/链上 | 交易所、代码、网络、币种、时区和频率标准化 | 同名资产不同网络分开；实时与历史、复权与原价不混用 |
| 企业/人员 | 按稳定标识匹配实体；保留来源间冲突与更新日期 | 同名不直接合并；“未知”不写成“没有” |
| 搜索/研究回答 | 区分候选链接、已读取正文、生成结论 | 每条重要结论能追到具体原文，而非循环引用 AI 摘要 |
| 天气/地理 | 统一坐标、单位、时区、观测/预测与模型批次 | 历史观测不与预测值混淆 |

## 建议的最小记录结构

| 字段 | 含义 |
| --- | --- |
| `source_platform` | 原始平台，例如小红书 |
| `access_provider` | 接入服务，例如 TikHub；与原始平台分开 |
| `source_id` / `source_url` | 原始ID与可回访地址 |
| `record_type` | 帖子、评论、文章、商品、行情等 |
| `published_at` / `collected_at` | 发布与采集时间分开；缺失保留 null |
| `raw_ref` | 原始响应或原始文件的存储位置 |
| `title` / `body` / `language` | 清理后内容及语言 |
| `metrics` | 指标值、单位和原始口径 |
| `parent_id` | 评论回复或其他从属关系 |
| `content_hash` | 辅助查重，不能替代平台ID与版本判断 |
| `quality_flags` | 时间缺失、正文截断、分页未完成等标记 |
| `transform_version` | 清理规则版本，便于重新处理 |

来源表登记的是“从哪里获得哪些能力”，实际业务记录才使用上述结构。不要把来源目录当成已经采集完成的业务数据库。

## 建议的最小验证任务

选择一个主题、两个来源、少量记录，在明确具体接口和费用后验证。这是后续实验设计，本轮尚未执行。

1. 核对来源支持的搜索、详情、评论及分页接口；明确账户条件和采集范围。
2. 保存原始数据，再进行字段映射、去重和质量标注。
3. 统计记录数、唯一记录数、缺失率、分页完整性与实际费用；不预设合格结果。
4. 人工抽查若干原文，确认清理未改变语义。
5. 让 AI 生成一个有引用的简报；检查结论是否能返回原文，并把推断单独标注。

只有跑通这一小段，才能判断某个来源是否值得用于长期研究或自动监测。来源名称多、返回 JSON、能生成报告，都不能替代这一步。
