# 产品思路与能力对比

## 核心判断

从我们的数据工作角度，主线可以定为 **来源 → 获取 → 清理 → 检索 → 分析**。但来源既可能是原始内容平台，也可能是中间数据服务，不能混成一层。三家自身的商业价值主要在于能力供给和稳定交付，清理只是其中一部分；AIsa 还提供模型和写操作。

| 层次 | 含义 | 例子 |
| --- | --- | --- |
| 原始来源 | 事实或内容在哪里产生/发布 | 小红书笔记、YouTube 视频、EDINET 披露 |
| 数据服务 | 谁替我们获取或组织数据 | TikHub、搜索服务、网站分析服务 |
| 聚合接入 | 怎样统一发现、调用、付费 | AgentKey、AIsa 的统一账户与接口 |
| 处理能力 | 拿到数据后怎样变得可用 | 正文提取、向量化、排序、去重 |
| 应用成果 | 用户最终得到什么 | 选题建议、竞品报告、趋势监测 |

一个服务可以跨层。比如 TikHub 同时提供查询入口与预处理数据集；AIsa 的目录既有原始平台名称，也有搜索、模型和业务操作。上表是研究者的分析框架。

## 搜索有三种，不能合并

1. **发现外部材料**：用关键词搜网页、帖子、论文，输出候选链接或记录。检索到不等于已读全文。
2. **检索我们保存的资料**：清理、索引后在本地库中搜索。需要我们建设索引、权限和更新机制。
3. **筛选或重排**：在候选结果里选最相关内容。AIsa 的 Jina Rerank 属于这里；排序不能修复错误事实。[AI05](https://aisa.one/api/embeddings-rerank-api)

同样，“Perplexity 返回带引用回答”包含模型生成，不应把回答文本当作独立原始来源再计算一次。

## 模型供应商与数据来源分开

AIsa 文档列出的模型家族包括 GPT、Claude、Gemini、Grok、DeepSeek、Qwen/Wan、Kimi、MiniMax、GLM、Seed/Seedream/Dreamina、Hunyuan、MiMo、HappyHorse。它们是推理或生成能力；具体模型 ID、版本和可用性需看运行时目录。本项目按模型网关登记，不把每个型号当作信息来源。[AI06](https://aisa.one/docs/guides)

Gmail、Notion 等名称也可能出现在 Skills 场景中。出现任务示例并不能证明它是无需账号授权的公共数据源，因而不混入来源总表。

## 对我们的产品设计意义

以下为研究建议，非三家官网承诺：

| 我们沉淀的资产 | 具体记录 | 带来的价值 |
| --- | --- | --- |
| 来源登记 | 原始平台、接入商、覆盖对象、证据、授权条件、接口状态 | 避免每次重新找来源 |
| 接入适配 | 参数、分页、返回字段、错误、调用成本 | 来源切换时减少应用改动 |
| 清理规则 | 去重键、时间/币种、作者与商品映射、缺失规则 | 数据能跨次比较 |
| 证据链 | 原始响应、内容 URL、抓取时间、转换版本 | 报告能追溯与复核 |
| 任务流程 | 何时查什么、何时停止、如何生成结果 | 从通用数据变成具体业务价值 |

供应商可以替换，原始记录、统一结构和业务判断应保持可迁移。三家能减少接入成本，但我们仍需验证来源适合具体任务，而非仅比较名称或接口数量。
