# 能力矩阵：输入、执行、输出与条件

研究基准及定位见 [来源索引](sources.md)。以下“具备”指文档或代码存在相应设计与实现，不表示本次已用真实服务跑通。

| 场景 | 用户输入 | 系统提供的动作 | 预期产物 | 需要什么 / 依据 |
| --- | --- | --- | --- | --- |
| 修复一个 Bug | 仓库、复现步骤、预期行为 | 代理检索代码、编辑文件、执行测试 | 差异、说明、可选 PR | 可运行仓库、模型、沙箱；S01–S05 |
| 增加网站功能 | 需求、约束、验收标准，可附图 | 修改代码、启动服务、使用浏览器 | 功能代码、命令结果、可选截图 | 服务启动方法、测试数据；S01–S02 |
| PR 审查 | GitHub PR 或评论中的指令 | 启动对应代码会话，分析改动 | 审查反馈；是否修改由任务决定 | GitHub Bot 与事件配置；S01 |
| 工单驱动开发 | Slack 消息、Linear 工单 | 集成服务把上下文转成会话任务 | 进度、结果和相关 PR 链接 | 每个入口的机器人/应用配置；S01–S02 |
| 多人协作 | 多人加入、追加指令 | 广播事件、记录作者、排队处理 | 同一会话的持续工作记录 | 共享同一部署与授权；S01、S03 |
| 并行处理同库任务 | 主代理给子会话的 title、prompt | 创建独立会话与沙箱 | 各子任务的结果与分支 | 子任务深度、总数和并发限制；S07 |
| 跨仓库联动修改 | 最多 10 个仓库或已保存的 environment | 在一个工作环境内并排获取仓库 | 分仓库提交的代码与 PR | 多仓库上下文、分别验收；S01–S02 |
| 定时批量维护 | 定时规则、仓库集合、同一指令 | 每个仓库启动独立会话 | 一次调度下各仓库的运行结果 | 仅定时类型支持多仓库 fan-out；S09 |
| 故障触发排查 | Sentry 告警、GitHub 事件或认证 Webhook | 条件过滤、去重、创建会话 | 调查结果；可要求尝试修复 | 事件送达、权限、上下文足够；S09 |
| 标准化开发步骤 | 技能指令和支持文件 | 解析适用技能、固定版本给会话使用 | 遵循约定的任务上下文 | 技能仍依赖模型与现有工具；S17 |
| 继续旧任务 | 原会话内的新要求 | 恢复工作环境并继续执行 | 新一轮改动和输出 | 供应商恢复能力及会话状态；S02、S12–S16 |

## 容易混淆的能力

| 问题 | 研究结论 |
| --- | --- |
| 它能自己写代码吗？ | 平台调用编程代理和模型，在沙箱中实际修改代码；下载源码本身还不能开始执行。 |
| 会操作我正在使用的电脑吗？ | 默认任务发生在它创建的远端开发环境；不能据此认为它自动接管本机应用。 |
| 关闭网页后工作会停止吗？ | 任务执行与网页连接分离；沙箱进程和控制服务仍受各自生命周期限制。 |
| 后台是否意味着永远持续运行？ | 不是；有执行超时、空闲停止、预算限制、失败和恢复路径。 |
| 多人是否会同时改同一个会话？ | 多人可以追加要求；单会话队列一次处理一条 prompt，当前上限为 50 条未完成 prompt（S20）。 |
| 多模型是否意味着模型同时讨论？ | 可选模型与运行层；单会话绑定一个运行层，不自动构成多模型辩论。Claude Agent 运行层限制为 Anthropic 家族（S06）。 |
| 并行子任务是否共享父任务未提交修改？ | 创建代码使用父会话的基准分支；本次未发现该路径传递父沙箱未提交工作区。使用时需明确提交与交接策略（S07）。 |
| 多仓库是不是自动合并成一次原子提交？ | 各仓库单独推送、创建 PR；没有由此得到跨仓库原子发布保证。 |
| 自动修复是否必然成功？ | 自动触发和可执行工具有依据；实际修复质量、回归风险和成功率需要任务级验证。 |
| 可以直接卖给互不信任的不同客户吗？ | 当前设计定位单租户、成员共享 GitHub App 仓库范围；多租户产品需额外隔离与授权设计（S01）。 |

## 三个可理解的派任务例子

以下是建议的试验输入，未实际执行。

1. **修复问题**：“订单列表在空数据时崩溃。请复现，修复，加入回归测试；提交 PR 并写清复现和测试结果。”交付重点是可审查的修复和回归证据。
2. **独立开发任务并行**：“任务 A 补充日期格式化函数测试；任务 B 改进 README 安装说明。”可以独立会话并行，最终仍需分别审核、处理合并。
3. **CI 失败触发**：“指定工作流失败时，分析错误与对应提交，说明原因；仅在可以复现且修改范围明确时尝试修复并提交 PR。”事件内容只是上下文，必须确保代理能够获得实际日志和运行依赖。

这些场景的价值在于任务派发、环境准备、执行与交付流程的连接。实际节省多少时间，应把部署准备、审核和返工也计入对照实验。
