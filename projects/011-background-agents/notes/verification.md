## 可复核的静态证据

在研究总仓库根目录执行（已有 checkout 时跳过 clone）：

```powershell
git clone https://github.com/ColeMurray/background-agents.git .cache/background-agents-research
git -C .cache/background-agents-research checkout 4c470da615eaecbf8f64b0ae5a04666c99b4c536
python projects/011-background-agents/src/collect_evidence.py .cache/background-agents-research
python scripts/catalog.py check
```

证据脚本只读指定提交的 Git 对象，要求 HEAD 与研究版本一致。它输出来源索引和文件哈希，不启动上游程序，不安装依赖、不读取凭据。完整上游 checkout 留作本机研究缓存，不属于正式成果文件。

## 下一阶段验收方案

| 实验 | 操作 | 通过标准 | 应记录的失败 |
| --- | --- | --- | --- |
| 单任务修复 | 用带失败测试的小仓库派修复任务 | 修复对应问题；原失败测试转绿；相关回归通过；差异可审查 | 依赖失败、扩大修改、测试被删或未运行 |
| 页面离线 | 执行中关闭网页，稍后重新进入 | 后台工作继续，结果和事件可查看 | 工作停止、事件丢失、重复执行 |
| 后续要求 | 原任务执行中再发一条要求 | 第二条排队，随后按顺序执行 | 抢跑、重复、错误丢弃 |
| 空闲后恢复 | 任务后等环境停止，再继续 | 工作区与对话恢复符合后端声明 | 文件缺失、依赖丢失、启动脚本失败 |
| 子任务 | 同一仓库启动两项独立子任务 | 各环境隔离；状态可查询；成果能明确交接 | 把未提交修改当作已共享、分支冲突 |
| 多仓库修改 | 前端/API 两仓库一起改接口 | 各自生成正确改动与 PR，联合验收通过 | 仅一端修改、版本不兼容 |
| 事件触发与去重 | 相同幂等键的认证 Webhook 重复发送 | 只创建预期运行；上下文正确传入 | 重复开任务、过滤不生效 |
| 故障与成本 | 设置失败任务和预算条件 | 状态明确、停止行为符合配置、费用可追溯 | 静默卡死、资源遗留、统计缺失 |

阶段验收要保存任务输入、仓库基准、部署配置版本、完整执行记录、测试与 PR 链接。只有取得这些证据后，再把相应能力标记为“端到端已验证”。
