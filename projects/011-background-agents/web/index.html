01

网页是控制台

你在这里发指令、选配置、看进度。它本身不负责执行代码。

02

代理程序是执行者

它调用模型，并使用工具真正读文件、改代码、运行命令。

03

模型提供推理

分析需求，决定下一步操作，再根据工具返回的结果继续判断。

WHAT IT DOES

具体能做什么，从哪里使用？

入口把需求变成任务，代理在配置好的开发环境中执行。

01

读写与修改代码

调查 Bug、增加功能、重构、补充测试。交付实际文件改动和说明。

02

执行命令与验证

安装依赖、构建、运行测试；可操作浏览器并截图检查页面。

03

提交代码供审核

通过 Git 推送分支，按任务要求创建 PR，供人检查与合并。

04

组织后台与并行工作

保存任务状态，派发独立子任务，按时间或事件启动工作。

任务入口

网页
新建会话，选择仓库、模型，输入要求。
Slack
私聊或 @机器人；在线程里继续交流。
GitHub
新 PR 自动审查；PR 评论或行内评论 @机器人。
Linear
在工单中提及代理，或将工单分配给代理。
Automations
定时执行，或由 GitHub、Sentry、Slack 消息触发。
Webhook
你的程序发送认证请求，触发已配置的任务。

各集成需配置。GitHub PR 评论入口主要用于分析与讨论；普通 Issue 的 @提及不走该评论入口。

HOW IT WORKS

一条任务，怎样从网页走到结果？

切换步骤看各层的分工。这里展示预设教学案例，不会发送真实任务。

任务要求

查明登录按钮没有反应的原因，修复问题，补充回归测试，并提交 PR 供我审核。

管理服务

先把需求存成一条任务

网页发送要求后，后台保存内容、作者和状态。如果同一会话已有工作，新的要求进入队列。

在这个例子中

保存登录问题的描述、目标仓库和验收要求，等待执行。

技术点：任务生命周期属于服务端，网页是输入与查看入口。

步骤 1 / 4

关闭网页不等于停止任务：进度保存在后台，执行发生在沙箱。任务仍受超时、预算和环境故障影响。

AGENT ≠ MODEL

接入的是代理程序，还是模型 API？

两层都需要。先选择负责执行的程序，再配置它使用的模型与认证。

OpenCode 可使用项目模型目录中的多个提供商。

接入关系说明 · 不配置真实账号

实际执行链

平台后台→OpenCode 程序↔OpenAI / Codex 模型

运行 OpenCode，调用 OpenAI 模型

平台在沙箱中启动 opencode serve，由它执行代理流程。模型提供推理，文件与命令操作由代理工具完成。

凭据方式
API Key，或项目支持的 ChatGPT 账号授权。
配置位置
部署密钥 / Settings → Provider Accounts；创建会话时选择模型和认证。

使用 Codex 模型，不等于启动 Codex CLI 或控制 Codex 桌面软件。

接入范围

OpenAI、Anthropic、xAI、OpenCode Zen / Go、Z.AI Coding Plan、DeepSeek。Zen / Go 提供 Kimi、MiniMax、Qwen、GLM 等模型渠道。实际可用性取决于账号、渠道和项目配置。

WHAT YOU CAN REUSE

内部值得借鉴的技术

这些设计也适用于资料分析、视频处理、报告生成等长时间 AI 任务。

01 / 调度

任务管理与执行分开

网页请求不一直等待 AI。后台记录任务，再交给工作进程处理。

可复用到：上传资料后异步生成报告
02 / 状态

持久化队列与事件

要求排队、状态保存、进度回传。刷新页面后仍能找到原任务。

状态保存不等于任何故障都能无损续跑
03 / 适配

统一代理执行接口

用开始、继续、停止和事件回传接口对接不同代理程序。

模型接入和代理程序接入分开设计
04 / 环境

隔离与环境复用

不同任务使用独立环境，通过预构建、快照或暂停恢复减少准备。

各沙箱提供商的恢复能力不同
