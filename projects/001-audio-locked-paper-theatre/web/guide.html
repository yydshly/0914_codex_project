这套方法，怎样把内容演出来？

用于培训视频制作、教学微课、技术科普、产品说明和知识传播。

画板是舞台

固定场景承载空间关系，让观众知道对象在哪里、过程发生在哪里。

物品是演员

球、盒子、卡片、设备是独立对象，可以移动、遮挡、传递和组合。

代码是动作脚本

分镜与程序规定对象的起点、终点、路径、状态变化和前后关系。

音频时间轴是演出节拍

读取配音的实际时间，计算这一刻每个对象的状态，让关键动作配合讲解。

制作顺序：讲稿与分镜 → 配音及时间戳 → 独立图层 → 动作编排 → 逐帧合成 → 验证视频。

对象之间的互动由代码预先编排。观众答题与拖拽属于额外交互；本地英语课已加入固定答案练习。

技术原理：声音怎样驱动画面？

画板是舞台，物品是演员，代码是动作脚本，音频时间轴是演出节拍。

可以把它理解为一个按讲解时间排练的纸艺舞台。盒子、桌子、小球、文字卡片分别是独立对象；程序规定它们什么时候出现、移动到哪里、遮住谁，以及怎样表现结果。

明确讲解目标 → 编写口播和分镜
→ 生成最终配音，取得真实音频与时间戳
→ 准备独立对象，确定位置、入口、出口和图层关系
→ 依据音频时间逐帧计算画面
→ 合成音频、动画和字幕
→ 检查音画同步、对象关系与完整成片

先锁定配音，是因为实际说话的节奏可能与估计不同。动画读取最终音轨的时间来安排动作，才能在说到一个概念时展示对应的变化。本地使用 MiniMax 返回的句级时间戳，句内动作另行编排，没有做逐词语音识别对齐。

这里的“对象互动”指画面中的小球进入盒子、请求卡传给服务器等动作。观众点击选项、接受答案反馈属于网页另加的交互层；英语页已实现固定答案练习，实时问答和发音评分还需要其他模块。

上游是制作流程、规则和验证工具组成的 Skill。它指导执行者调用语音、图像、渲染等工具完成作品。我们的四个样例采用自编 Pillow 画面合成与 FFmpeg 编码，复现这套方法。它们保留了独立素材和可重渲染代码；已经导出的 MP4 本身是一段固定视频。

这种效果的价值在于把位置、步骤、因果和状态变化演出来。例如讲 in 时，让同一颗小球进入盒子并被前壁遮挡；讲 on 时，让球接触桌面。是否真正帮助学习，应通过学生复述、选择或迁移应用来验证。

从音频到动画，具体发生了什么？

  1. 取得实际时间。 MiniMax 生成配音，返回每句实际开始与结束时间；本地英语课的三句位置描述分别约从 14.4、28.5、40.7 秒开始。
  2. 把语义写成动作规则。 “in” 对应球进入盒子，“on” 对应球底部接触桌面，“under” 对应球移到桌下。配音提供时间信息，分镜和代码负责这些语义对应。
  3. 按进度计算位置。 假设移动安排在第 26～28 秒，进度为（当前时间 − 26）÷ 2，并限制在 0～1。根据进度计算起点到终点的位置，加入缓动或弧线可改变运动节奏与路径。
  4. 按图层绘制每一帧。 背景、盒子后部、球、盒子前壁、词卡和字幕依次绘制。前壁遮住球的一部分，表现球在盒内。24 fps 意味着约每隔 0.0417 秒计算一帧。
  5. 合成并校验。 将连续画面与固定音轨合成为 MP4，检查动作是否对应讲解、字幕是否重叠、成片是否完整可播放。

“定时”可以理解为按同一条时间轴计算状态：到了哪个时间，就绘制那个时间应有的画面。导出时并不依赖操作系统定时器恰好按时触发。更换配音或语速后，应重新取得时间戳并调整动作安排。

因此，这是一种适合培训视频制作和解释型微课的程序化动画方法。网页中的暂停、章节跳转和固定答案练习进一步支持课堂使用；实时互动、智能评分与个人学习记录需要额外模块。

三、如何用于个人学习？

1. 把难懂的材料变成可视解释

输入一段教材、论文或技术文档，先抽取核心问题和关键关系，再制作有声分步解释。材料解析、检索和事实核对需要其他工具承担。

例：阅读数据库事务资料，选择“为什么两个操作需要一起成功或一起失败”作为学习目标，用两张记录卡及状态变化展开说明。

2. 把解题或操作方法拆成步骤

先展示题目或任务，再逐步增加中间状态，说明每一步为什么成立。正确性来自学科知识与核对；动画负责把推理过程显示出来。

3. 比较容易混淆的概念

把两种概念放在同一舞台，使用相同的例子逐项比较。例如进程与线程、栈与队列、相关与因果。

4. 把自己的复述做成学习作品

学习者先讲清楚，再将复述整理成配音稿和分镜。此时暴露出的逻辑跳跃、没有依据的结论、说不清的对象关系，可以用于安排后续学习。视频制作不等于掌握，需要再检查理解和迁移应用。

5. 形成可复习的知识材料

同一份内容可以扩展为讲解视频、关键帧图解、文字提纲和复习题。后面几种产物需要补充导出与出题流程。

6. 支持主动回忆

在视频中设置“先想一想”“预测下一步”“找出错误”等暂停点，随后展示答案。我们已经实现了暂停练习与答案跳转；自动记录作答、判断掌握度和安排复习尚未实现。

推荐的学习闭环

资料与学习目标
→ 确定先备知识和容易误解的地方
→ 生成视觉讲解
→ 学习者复述或作答
→ 检查理解与错误
→ 补充解释与再次练习

本库重点支持“生成视觉讲解”。它不包含通用的自主学习、学习者长期记忆或个性化辅导系统。

五、它与 PPT 的四种组合方式

A. 已有 PPT → 有声解释视频

读取 PPT 的观点、数据和讲者备注，重写口播与分镜，再制作有声视频。需要读取演示文稿的工具；复杂图表和图像需要保留来源与准确性。直接把每页当作固定背景只是在播放幻灯片，不一定发挥独立对象动画的价值。

适合：把课件、产品介绍、内部培训材料制作成可重复观看的讲解内容。

B. 视频分镜 → 图文 PPT

抽取关键状态作为页面图片，加入标题、解释和备注，可以制作便于展示的课件。需要 PPT 生成工具。

关键区别：视频截图中的卡片和文字是图片像素，不能直接变成可独立编辑的 PowerPoint 元素。

C. 结构化内容 → 可编辑 PPT 与视频

先建立共享的内容结构：标题、概念、对象、关系、步骤、配音、讲者备注、来源。视频渲染器把它编成动画；PPT 生成器把它排成原生文本框、形状与图表。

这一路径有利于内容一致性和修改，但需要新增共享数据结构、PPT 排版与检查流程。PPT 的点击顺序与视频的绝对时间线不同；动画通常需要单独重建，或直接嵌入视频。

D. 一份内容 → 多种教学材料

同一份经过核对的教学内容
├─ 有声解释视频
├─ 可编辑 PPT 与讲者备注
├─ 图文讲义
├─ 学习提纲
├─ 练习题与答案
└─ 课后复习卡

这是扩展方案，而非当前仓库开箱即用的功能。最关键的是让这些产物共享同一份内容来源，而不是分别生成后再修正不一致。

七、哪些情况价值较低？
  • 一句话就能说明白的事实：文字通常更省时。
  • 用户要快速定位某条信息：可搜索的文档、目录和 FAQ 更合适。
  • 必须准确看到软件操作：录屏与可操作环境更直接。
  • 需要真实手法或身体动作：实拍和实操反馈更重要。
  • 需要随时修改参数观察结果：交互式图表或仿真更合适。
  • 需要大量公式、代码逐字阅读：文档或课件更便于停留与查阅。
  • 内容更新很频繁：先建设结构化内容源，否则反复配音和渲染的维护成本会增加。
  • 主要诉求是人物情绪、现实质感或复杂三维空间：纸艺风格需要与其他表现形式结合。
八、选题检查与效果验证

优先考虑满足这些条件的内容：

  1. 对象、角色或概念能清楚命名。
  2. 存在值得展示的关系、变化或步骤。
  3. 观众看过后应当理解某个具体问题，或完成一个具体动作。
  4. 内容值得重复观看、分享或用于多批次培训。
  5. 能取得足够准确的资料、数据和素材。

评估时不要只看画面是否漂亮。可以比较观看前后的概念理解、任务完成情况、错误类型和一段时间后的回忆。若没有学习或业务指标，最多只能证明视频完成并可播放，不能证明教学有效。

九、对当前子项目最自然的扩展方向
  1. 技术学习包：源码或技术文档 → 核对后的原理讲解视频 + 架构图 + 阅读提纲。
  2. 教师备课包：教学目标 → 微课视频 + 可编辑 PPT + 讲义 + 练习。
  3. 企业培训包：批准的岗位流程 → 角色与步骤演示 + 纠错案例 + 测验。
  4. 个人复习包：已学内容与错题 → 重点解释 + 主动回忆题 + 图文复习卡。
  5. 统一内容生产：同一套内容数据同时驱动视频、课件和讲义，更新时同步生成各版本。

这些扩展应按具体需求逐步实现；当前已完成的是四个有声演示、本地播放和验证流程，以及英语固定答案练习。尚未接入发音评测、学习档案或自适应辅导。
