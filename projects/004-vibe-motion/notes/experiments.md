# 首轮实验与验证记录

后续二维视频、两个动效与网页验证见 [网页补充研究](gallery.md)。下文保留首轮实验范围。

日期：2026-09-16。环境：Windows、Node.js v22.15.0、Python 3.10.11、本地 Chrome、FFmpeg。三维工程使用 three@0.161.0、puppeteer-core@24.41.0，完整依赖固定在 [package-lock.json](../src/demo-3d/package-lock.json)。

## 1. 脚手架生成

运行两个固定版本仓库的模板同步脚本和本地CLI，以 --skip-install 生成项目：二维生成到 .cache/demo-2d；三维生成到 src/demo-3d，均成功。三维安装依赖并生成锁文件，其 npm run verify 的三个语法检查通过。未安装完整二维依赖或渲染React场景。

三维场景、HTML、场景控制和导出服务保持上游模板字节一致。研究脚本在工程外部调用接口，并未改写动画逻辑。

## 2. 二维逻辑实验

运行 `node src/probe-2d.mjs` 直接调用上游原始函数。[原始结果](probe-2d-results.json)。

| 问题 | 实测结果 |
| --- | --- |
| 默认时长 | 3秒×30fps=90帧 |
| 先请求别帧后再请求同帧 | 第45帧参数相同 |
| 非循环请求第95帧 | 停在第89帧 |
| 循环请求第95帧 | 返回第5帧 |
| 请求1920×1080 | 模板标准化为1280×1080 |
| 音轨独立时间与音量 | 起点30、时长60、音量0.8保持正确 |
| 文件缺失 | 移除缺失音轨引用，保留现有音轨 |

7项检查全部通过。这不证明实际音频播放、音画对齐或React画面效果。

## 3. 三维原始模板导出

请求上游接口导出0–89帧，收到90个顺序正确的PNG；由FFmpeg合成为 [MP4](../assets/demo-3d.mp4)。[渲染原始结果](render-results.json)。

| 核验项 | 结果 |
| --- | --- |
| 分辨率 | 2048×1152 |
| 帧率 / 解码帧数 | 30fps / 90帧 |
| 时长 / 格式 | 3.000秒 / H.264、yuv420p |
| 音轨 | 无 |
| 独立浏览器导出第45帧，与序列比较 | PNG字节完全相同 |
| 负帧号 | 截断到第0帧，PNG相同 |
| 超出结尾帧号 | 截断到第89帧，PNG相同 |

视觉检查了第45帧，标题、几何环、方块和网格正确出现；没有对90帧逐帧人工审片。重复帧只验证了当前环境的样本一致性，未测试其他GPU或浏览器版本。

## 4. auto-motion源码检查

已阅读任务说明、单镜脚本、测试入口和验证器。确认分镜依赖智能体，同一时间一个Claude调用，输出静音1080×1440、30fps。验证器固定测试约1秒的scene-001和final.mp4，并非通用多镜头验收器。

没有运行模型链路，未测生成耗时、费用、自动修复率、长片结果和素材搜索质量。阅读端到端脚本不等于端到端测试通过。

## 5. 资料一致性

`python -X utf8 src/verify.py` 检查源码哈希、15个顶层Skill、三维复制文件、研究文档链接、实验结果与实际视频规格。根目录运行 `python scripts/catalog.py check` 检查登记与首页同步。
