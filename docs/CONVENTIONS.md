# 项目组织与维护

## 编号与排序

- 正式项目目录为 `projects/001-project-name/`，从 `001` 递增，至少三位数字。
- `id` 是永久编号，不因展示顺序变化而修改，不复用已分配的编号。
- `slug` 使用小写英文、数字和单个连字符。
- `order` 是正整数，决定首页显示顺序。建议以 10 为间隔，方便插入；同值时按编号排序。
- 已结束的项目保留登记并设为 `已归档`，以保存编号和引用链接。
- 模板不计入索引，也不占用编号。

## 登记字段

`projects.json` 是首页内容的唯一数据来源，每个项目包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 字符串编号，例如 `001` |
| `order` | 首页展示顺序，例如 `10` |
| `slug` | 目录后缀，例如 `example-repo` |
| `name` | 项目显示名称 |
| `repo` | 上游仓库的 HTTPS 地址 |
| `summary` | 一句话研究摘要 |
| `status` | `待研究`、`研究中`、`已完成`、`已归档` |
| `tags` | 技术 / 主题标签列表 |
| `cover` | 封面相对仓库根目录的路径；无图时留空 |
| `cover_alt` | 解释图片内容的文字 |
| `demo` | 已部署演示的 HTTPS 地址；未部署时留空 |

不要填写尚未发布的演示地址，不用占位图冒充实际截图。封面建议使用 PNG、JPG、WebP、GIF 或 SVG，优先控制到 1 MB 以内；更多图片放在子项目 README 中。

## 常用操作

```sh
# 新建项目并刷新首页
python scripts/catalog.py add example-repo --name "示例项目" --repo "https://github.com/owner/example-repo" --summary "研究摘要"

# 修改登记表后刷新首页
python scripts/catalog.py sync

# 校验元信息、目录、图片及首页是否同步
python scripts/catalog.py check
```

首页两个注释标记之间的内容由脚本维护，其余介绍文字可自由编辑。同步前会检查数据；CI 发现过期索引时会失败，需要在本地运行 `sync` 后提交。

## 子项目边界

各子项目独立管理依赖、锁文件与运行说明，不要求使用相同技术栈。根目录仅管理导航和共享约定。

优先记录上游链接与版本，将研究中实际需要的代码放入子项目。若复制上游文件，保留其许可证和版权说明；如后续需要长期跟踪完整上游，再按项目选择 submodule 或其他同步方式。

研究日志写入 `notes/`；首页摘要保留最终结论或当前重点，避免堆积长篇日志。
